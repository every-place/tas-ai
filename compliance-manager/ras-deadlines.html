RAS Compliance Calendar

Every deadline in the Texas Architectural Barriers Act program that a Registered Accessibility Specialist or owner has to track, written as one table of rules: the event that starts the clock, the offset, who acts, and the document that comes out. Below it is a working sketch of how recorded dates turn into calendar tasks and pre-filled letters.

What the rules come down to

  1. Five dates drive almost everything: plans issued, construction complete, inspection date, inspection report date, and the date the owner's response is received. Record those and the system can schedule the rest.
  2. Most clocks are 30 calendar days. Only one rule counts business days: design professionals submit plans to a RAS within 20 days of issue, not counting Saturdays, Sundays or legal holidays (68.50(a), Gov't Code 469.102).
  3. The 270-day correction window starts from the inspection report date in the rule (68.52(d)(2)), but the prescribed letter paragraph says "270 calendar days from the date of this letter" (Bulletin 2023-05). Dating the letter and report the same day removes the conflict.
  4. Letters are assembled from nine prescribed paragraphs (results, owner action, disclaimer) published in RAS Bulletin 2023-05 under 68.53(b)(6)-(8). Five letter types cover every case, so letter generation is a lookup, not free writing.
  5. Some dates in the rules disagree or are vague. Seven are listed under "Open questions in the rules", each with a proposed default. The calendar should show both dates where the rules conflict and treat the earlier one as the deadline.

Open questions in the rules

These are places where the rule text is silent, ambiguous or in conflict. Each ships with the proposed default and can be changed later as a setting, so none of them blocks building or field testing.

How recorded dates become tasks

The engine never stores a deadline someone typed. It stores events (a date plus a source document), and each rule above says "when this event happens, create this task, due this many days later." Finishing a task records a new event, which starts the next rules. Change a date and every open task downstream moves with it, with the old date kept in the history.

Rules live in data, not code. When TDLR amends Chapter 68 (it already promised to fix the 68.40(d) cross-reference and add the letter paragraphs to the rule), the firm edits rows instead of waiting on a developer.

Letters from paragraphs

68.53(b) lists the fields every transmittal letter needs (report date, RAS name and certification number, owner name and address, TABS project number, project name, facility name and address), then up to three paragraph blocks. RAS Bulletin 2023-05 supplies the required wording for those blocks. Each letter type is a fixed recipe:

Paragraph text here is a summary. The app would store the bulletin's exact wording once, with fields such as {report_date} marked, so every letter uses the prescribed language. The findings list attached to the report comes from the Report Writer module, using the same project and TABS number.

How it connects to the other modules

The Compliance Manager owns projects, events, tasks and letters. Plan Review and Field Inspection record the events (plan review finished, inspection date, findings count). Report Writer produces the report, and its issue date becomes the report_issued event that starts the 30-day and 270-day clocks. Owner responses and correction photos come back in as events too, so the corrective modification letter can list exactly which findings are still open.
